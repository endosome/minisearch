# Performance project: final results

The repository's public benchmark (`differential/bench_public.mjs`: the public API against MiniSearch 7.2.0, 20,000 documents, 39 queries, 9 paired rounds, medians) on the machine and toolchain of the [WP-00 baseline](2026-10-15-wp00-baseline.md): Intel Xeon E5-2640, Linux, Node 24.22.0. The build is `1ef51fb`. Every result row was verified against MiniSearch: 934,016 rows, maximum relative score difference 0.

MiniSearch's own timings vary between the two runs by up to 10%: the runs are paired within themselves, not with each other. The speedup columns are each run's ratio. Same-package comparisons, which cancel that drift, are in the Phase 4 cumulative A/B: default `search()` 0.587× the baseline's time, dirty first pass 0.108×, compaction 0.592×.

## What changed, in one line each

- **Full-object `search()`, the primary workload: 2.82× → 4.06× MiniSearch.** One engine execution per call (WP-01), row data tracked only when a result needs it (WP-02), per-document scratch slots (WP-07), and rows built into preallocated arrays.
- **Indexing at scale:** 1M documents in 38 s instead of 200–357 s. Wasm memory now grows geometrically; each small grow had cost V8 a full garbage collection.
- **Memory:** 12% less live memory for the facade's indexes (WP-08), plus exact first allocations for the many one-document terms (WP-12).
- **Maintenance:** O(1) `termCount`, compaction 0.59× and vacuum 0.81× the baseline's time.
- **New opt-in methods:** `searchTopK`, `searchScores`, `countMatches`, each defined by `search()` and 0.34–0.45× the time of the `search()` expression.
- **Compatibility:** two stored-score divergences from MiniSearch fixed. Snapshot formats unchanged. The compact calls' term tables are unchanged.

## Not changed

The compact calls (`searchJoined`, `searchRaw`, `autoSuggest`) stay at about their baseline speed: within a few percent in the same-package A/B. Their cost is posting traversal, which no measured experiment made cheaper (ADR 0002). `addAll` with a `processTerm` callback and the JavaScript-engine fallback are bound by JavaScript and unchanged.
